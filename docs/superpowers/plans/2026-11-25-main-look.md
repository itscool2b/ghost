# Main: the full styling pass (app, website, remote)

Owner, 25 November 2026: "the greatest styling pass of all time" for the desktop app, the website and the remote page, and a standing rule that everything built afterwards meets the same bar. This file tracks the pass. The look itself is described in [visual-language.md](../../design/visual-language.md), the references in [reference-audit.md](../../design/reference-audit.md).

## What was asked

- **App**: a new default look called Main. Not only colours: shape, type, spacing, icons and the message box, on every surface (sidebar, projects, new project, onboarding, new chat, every settings page, terminal, browser, phone, changes, menus, dialogs). Models: the Grok Bot desktop app and the Synara ADE, as looks only.
- **Website**: dark, no coloured wings, on the level of polar.sh, linear.app, ghost.ai and x.ai/bot, with a smart showcase of what the app does.
- **Remote page**: as good as the rest.
- **Afterwards**: every feature and every site addition ships at this standard ([developing-in-ghost.md](../../developing-in-ghost.md), "Looks").

## Decisions

1. The website is always dark: no light variant, no system switch.
2. Main is o7's own neutral palette (the slot once called Aura; its saved name is unchanged), retuned and made the default. A profile still on the earlier default, Claude Code's theme, moves to Main once. A profile that picked another theme keeps it. Every agent theme stays and wears the same shapes.
3. Pills stay. Density and precision come through rows, menus, tabs, icons and the message box.
4. Icons stay Lucide, drawn thinner through one token.
5. Geist stays, in the app and on the site.
6. Sidebar chat rows stay one line and gain the chat's agent mark and a quiet time.
7. The site takes polar.sh's skeleton, Linear's fading product compositions, one scroll sequence in the spirit of ghost.ai, and the live app window. A monochrome grain stage is texture, not a glow.
8. Styling only: no new features. The iPhone app takes the new palette through its generated colours; its own pass is not part of this one.

## How each step is checked

- While building: the desktop's `?preview=` states and the site's dev server, opened in o7's own browser in both appearances and compared with the references.
- Per change: `pnpm lint`, `pnpm typecheck`, the `@o7/ui` and `@o7/desktop` unit tests.
- On GitHub: the Check workflow with the browser suites for each app change, Rust tests and the bindings check for the foundation, the full CI workflow (layout checks in both engines and appearances) before the last app merge, the iPhone app workflow for its generated palettes.
- Website: its static and browser tests, then the preview deploy walked at 1440, 1024, 768, 390 and 320 wide, without JavaScript and under reduced motion; the live site again after the merge.
- Not covered by eye until the next approved build: native window chrome (caption and material), which the pinned Rust test and the material preview stand in for.
