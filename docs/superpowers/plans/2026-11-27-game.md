# Ghost for game development: Game, the third universal plugin

Owner, 27 November 2026: make Ghost the place to build games with coding agents, "in a really
sexy and cool way", with the research and the choices left to the agent doing the work. How what
is built works is in [docs/game.md](../../game.md); this page is the plan, the research behind
it, and a log of what is done.

Ghost already gives every agent a browser (`ghost_browser`) and a phone (`ghost_mobile`) beside
the chat. A game needs the same thing and more: the agent has to run the game, see it, play it and
read its insides, and the person has to be able to play it and point at what is wrong.

## What the research found

| Engine | What it is | How agents reach it today | Ghost's part |
| --- | --- | --- | --- |
| Web (Three.js, Phaser, Babylon, PlayCanvas, plain canvas) | A game that is a web page, shared by a link. Three.js was 65% of the 945 entries in Vibe Jam 2026 | A browser | First class: Ghost already has the browser |
| Godot 4.7 | Free, open (MIT), an 86 MB download, projects are text files an agent can read and write. The fastest growing engine | No official way; a dozen community MCP servers | First class: Ghost runs it itself |
| Unity 6 | Most games by count. A multi-GB editor, an account and a licence | Unity's official CLI, agent plugin and `unity mcp` | Connect to Unity's own tools |
| Unreal 5.8+ | Most money earned. A very large install | An official MCP server inside the editor | Connect |
| Roblox Studio | Games inside Roblox | An MCP server built into Studio, with playtest automation | Connect |
| Bevy, LÖVE, Pygame, GameMaker, Defold, MonoGame | Smaller, code-first | A shell | Detected and named |

What matters, from the sources:

1. The loop is everything. Writing game code is easy for agents; knowing whether it works is not.
2. Screenshots alone are too slow for a game that moves: the game keeps running while the agent
   thinks. Time has to stop for the agent.
3. One still picture hides motion. Agents need a strip of frames.
4. Agents can judge whether a game is broken or balanced, not whether it is fun. The person still
   plays, so playing and pointing must be effortless.
5. Others place an editor's window in a pane, or live inside one engine's editor. Nobody found
   freezes time for the agent or replays a person's play exactly.
6. Shipping: itch.io is free, Steam costs $100 a game and takes 30%, a web game is files on a host.
7. Art and sound come from generators with their own agent tools. Ghost should show and preview
   what they make, not be a generator.

## Decisions

- **Two engines Ghost runs itself: web and Godot.** Both are free with no account. Unity, Unreal
  and Roblox get a Connect card that wires in the vendor's own official tools; Ghost never
  downloads or imitates those editors. Why not run them ourselves: they are very large, need
  accounts and licences, and each vendor ships official agent tools that keep improving.
- **Godot is fetched once, on the person's click**, pinned by the checksum Godot publishes: never
  bundled (an update package must stay under 512 MiB) and never by an agent. A Godot already on
  the machine at a fitting version is used instead. GDScript projects only at first.
- **The game is a stream in the pane, like the phone.** A small script Ghost owns runs inside the
  game and sends frames, takes input and answers questions. The game's real window stays out of
  sight; a window of its own is one press away.
- **Frozen time.** While an agent drives, the game is frozen. An action runs in game time at a
  fixed step, then the game freezes again and the agent gets a filmstrip of the action, the last
  frame, and any new errors. Fixed steps make runs repeatable.
- **Agents only get the tools in game projects**, or where the person turns Game on for a chat.

## Who may do what

- **Only the person**: fetch Godot or export templates, connect another engine, give the game a
  window of its own, export, upload.
- **Agents** (native chats only, a per-session token, the switch read on every call): run, see,
  drive, inspect and change this chat's game. The project folder comes from the grant, never from
  the caller. `game_eval` runs code inside the person's own game, which an agent can already do
  by editing the game's scripts; Settings says so.
- **The game** is untrusted: it can only answer and send frames, sizes are capped, and names, text
  and logs from it are data, never instructions. Loopback only; no remote or bot access.
- One game a chat, two running at most, stopped after ten idle minutes and at quit.

## Risks

- macOS and Wayland may show the game's own window behind Ghost.
- Smart App Control may block a freshly fetched Godot on some Windows computers.
- The web time shim does not reach iframes or workers.
- The vendors' tools for Unity, Unreal and Roblox are new and still changing; the cards probe and
  say what they find.
- Not in this plan: embedding the Godot editor or Blender in a pane, C# and Godot 3 projects,
  running Unity or Unreal ourselves, generating art inside Ghost.

## Log

**M0, Godot (Windows 11, Godot 4.7.2 from the official zip, SHA-512 matched `SHA512-SUMS.txt`).**

- A bridge without touching the project: `godot --path <project> -s <Ghost's loop.gd>` loads a
  `SceneTree` subclass from outside the project. The project's autoloads load, the loop adds the
  bridge node and opens the main scene. Nothing is written into the project.
- Frames: `get_viewport().get_texture().get_image()` takes 1.1 to 1.5 ms and a JPEG at 960x540
  3.8 ms, enough for 30 a second.
- `--fixed-fps 60 --disable-vsync` gives a delta of exactly 1/60 s and exact repeats (30 frames of
  "right" move a 200 px/s player exactly 100 px). It ignores `Engine.max_fps`, so the bridge
  itself keeps real time while a person plays.
- Out of sight on Windows: a hidden start is ignored and `--wid` alone still shows and takes
  focus. What works is `--wid <Ghost's window> --position 30000,30000` (an owned window with no
  taskbar entry that still draws) with a foreground lock held across the start.
- Errors with file, line and stack come from Godot's `Logger` class (4.5 and later).

**M0, web (Three.js 0.170 and Phaser 3.87 in Ghost's own browser).**

- Wrapping `requestAnimationFrame`, `performance.now` and `Date.now` before the game loads
  freezes it and steps it: 30 steps of 1/60 s moved a Three.js cube exactly half a second.
- `canvas.toDataURL` right after a frame's callbacks gives a real picture of a WebGL canvas.
- Three.js announces every scene and renderer to `window.__THREE_DEVTOOLS__`, bundled or not.
  A bundled Phaser has no outside hook: its tools will ask the game to keep itself on
  `globalThis.__GHOST_GAME__`.

**M1.**

- `crates/ghost-fetch` and `crates/ghost-game`, with `ghost-devices` unpacking through the same
  unzip. The real-Godot test passes on Linux under a virtual display: Godot fetched and checked,
  then every tool against a fixture game.
- One bug the real engine found that the stand-ins had not: Godot writes whole numbers that came
  from JSON as floats, so a request's id came back as `7.0` and no answer matched its question.
  Both ends now treat a whole number as one however it is written.
- `ghost-core`'s `game_service` (the grant, the helper, the instructions and skill), the session
  wiring, the `game` preference, the desktop's `game.rs`, the pane, Settings > Game, the preview
  and `check-game.mjs`, the tour stop.
- Checked natively on Windows before the merge: Godot fetched by the pane's button, no window and
  no focus change, 60 frames a second, the keyboard through the pane, every tool, a real agent's
  turn through the grant, Turn on Game for a chat, the game's own window and back. The **Godot
  game** workflow passed on main.

**M2.**

- A change from the plan as first written: the web game stays in the Browser pane instead of
  getting a tab kind of its own inside the Game pane. A web game is a page, the person already
  plays pages there with real input, and a second host for the same page would have been a
  second place for the same bugs. What the milestone was for (frozen time, exact steps,
  filmstrips, the same tools) is all there, on the chat's own tab.
- The clock is armed per tab without touching the host: `game_run` marks the page in its own
  session storage and loads it again, and the page script, which every page already gets before
  its own scripts, wakes the clock only where it finds the mark.
- Timers are on the game's clock as well as frames, so half a second of game time fires five
  ticks of a 100 ms interval whether it took half a second or five milliseconds.
- A review of the first cut found that the new tools returned page text without the browser
  tools' password guard. Every answer now passes it, and the tools that read a page's insides
  work only in a page marked as a game.
- Checked natively on Windows in the app's real browser: a canvas game opened with its clock
  held, half a second of ArrowRight exactly 100 pixels twice, a wait, the console, live again,
  and back to its own time.

**M3.**

- Start a game is in the Game pane's "No game here yet", not in New chat as first planned: the
  pane is where the question "what is in this folder" is already answered, and a new chat in an
  empty folder reaches it from the More menu. Four starters of Ghost's own, each a player that
  moves and jumps on a floor: Godot 2D and 3D, a plain canvas page with a small server of its
  own, and Three.js with Vite. The real-Godot test loads and plays both Godot ones.
- The makers' steps on the Connect cards were read from their own guides on 27 November 2026:
  Unity's agent plugin and CLI pages, Epic's "Unreal MCP in Unreal Editor" (for 5.9), and
  Roblox's "Connect to the Roblox Studio MCP server". Unity's in-Editor MCP server is deprecated
  in favour of its CLI, which configures each agent itself, so Ghost adds no server for Unity.
- A review found the canvas starter's server answered any Host: a page elsewhere could have
  pointed a name of its own at it and read the project's files through the person's browser. It
  now answers only as localhost, serves no hidden file, and has a test.

**M4.**

- Replays are from the run's start, not from fifteen seconds back: a game cannot be wound
  back, but under `--fixed-fps` every step is the same length, so the whole run's inputs with
  their step numbers reproduce it. The fifteen seconds are what the filmstrip shows; the tape
  is the whole run.
- Exactness took two changes to the bridge. The game is now stopped and started only between
  frames (it was paused mid-frame, which made half steps a replay could not repeat). And a run
  held for a replay takes its first step before it stops: stopping it before that step put its
  scene in the tree one step early, and the first test replay ended one frame ahead (92 against
  91). With both, a run an agent set up, an agent played and a person played live replays to
  the same frame count, score and position.
- `game_set` and `game_eval` go on the tape too. The first cut only warned that a replay does
  not repeat them, which would have been said of nearly every run: agents read the game with
  `game_eval` all the time.
- Pointing does not use the physics engine. It takes the smallest box under the pointer among
  what Ghost can measure, which also finds things with no collider (a label, a sprite).
- The controller is the least certain part: there is no controller on the machine this was
  built on. Godot reads the computer's controllers itself, even out of sight, so the pane sends
  its own only when the game says it sees none. That rule is from Godot's documented behaviour,
  not from a test with hardware.
- Web games get none of M4. The person plays a web game in the browser with real input, which
  Ghost does not record, and the browser's Annotate already points at a page's elements.
